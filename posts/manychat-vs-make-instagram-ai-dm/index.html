Contact Pricing vs Credit Pricing: Real 2026 Math

Suppose a viral Reel drives 5,000 unique commenters in one week, and your AI bot exchanges 3 messages with each user (15,000 messages total):

  • On ManyChat: Because billing scales by Active Contacts, crossing 2,500 contacts bumps you toward the Business tier (~$69/month for ~7,500 contacts)—and if you keep accumulating contacts up to 25,000 without pruning cold leads, you reach ~$139/month.
  • On Make: You pay strictly for active executions, not stored contacts. However, a 5-module AI scenario running 15,000 times consumes 75,000 credits, pushing you up to a higher credit bundle—AND you must build and maintain your own Meta Developer App, token refresh logic, and 24-hour messaging window compliance.

Why Most Production Teams Use the Hybrid Webhook Pattern

If you try to run raw Instagram Graph API webhooks directly in Make or Python from scratch, you spend days fighting Meta App Review (instagram_manage_messages), webhook signature verification (X-Hub-Signature-256), and rate limits.

The cleanest engineering pattern in 2026:

  1. ManyChat captures the Reel comment or DM keyword ("PRICE" or "DEMO") natively with zero Meta App Review headaches.
  2. ManyChat External Request (Webhook) sends the user's message and subscriber_id to your FastAPI endpoint (or a Make / n8n webhook).
  3. Your backend runs RAG lookup or lead qualification, pushes the verified email into Systeme.io for evergreen email nurturing, and returns a short reply to ManyChat.
  4. Every 30 days, you archive cold ManyChat contacts whose emails are already synced to your CRM—keeping your ManyChat contact tier flat.

Copy-Paste Python FastAPI Webhook Handler for ManyChat External Requests

Here is a minimal, production-safe FastAPI handler that verifies a shared secret header, qualifies the DM payload, and returns ManyChat's native dynamic response format:

import os
from fastapi import FastAPI, Header, HTTPException
from pydantic import BaseModel

app = FastAPI()
WEBHOOK_SECRET = os.environ.get("MANYCHAT_WEBHOOK_SECRET", "change-me")


class DMWebhookPayload(BaseModel):
    subscriber_id: str
    first_name: str = "there"
    last_input_text: str
    email: str | None = None


@app.post("/webhooks/manychat-ai")
async def handle_manychat_dm(
    payload: DMWebhookPayload,
    x_webhook_secret: str = Header(default=""),
):
    if x_webhook_secret != WEBHOOK_SECRET:
        raise HTTPException(status_code=401, detail="Invalid webhook secret")

    user_msg = payload.last_input_text.strip().lower()

    # Replace with your OpenAI / Claude / RAG call (keep timeout < 6s)
    if "pricing" in user_msg or "cost" in user_msg:
        reply = (
            f"Hey {payload.first_name}! Our starter stack runs under $15/mo. "
            "Drop your email and I'll send the full comparison breakdown."
        )
        intent = "high_intent_pricing"
    else:
        reply = (
            f"Thanks for reaching out, {payload.first_name}! "
            "Tell me which tool you're automating and I'll point you to the blueprint."
        )
        intent = "general_inquiry"

    # Native ManyChat v2 dynamic content response
    return {
        "version": "v2",
        "content": {
            "messages": [{"type": "text", "text": reply}],
            "actions": [
                {
                    "action": "set_field_value",
                    "field_name": "ai_lead_intent",
                    "value": intent,
                }
            ],
        },
    }

Three guardrails before going live:

  1. Respect ManyChat's 10-second webhook timeout: Keep LLM responses fast (use lightweight models for classification and short replies) or return an immediate acknowledgment and push the full answer via ManyChat's /fb/sending/sendContent API asynchronously.
  2. Respect Meta's 24-hour window: Instagram only permits automated DM replies within 24 hours of the user's last interaction. Capture their email inside the first two turns and hand off long-term follow-up to Systeme.io.
  3. Deduplicate webhook retries: Cache subscriber_id + message_hash in Redis for 60 seconds so Meta/ManyChat retries never send double DMs.

Frequently Asked Questions

Is ManyChat or Make cheaper for Instagram DM automation in 2026?

For small audiences under 2,500 contacts, ManyChat Pro (~$29/mo annual) is predictable and includes native Meta integration. Make Core (~$9–$12/mo for 10,000 credits) is cheaper per operation for backend routing, especially if you combine ManyChat for triggers with Make for CRM/AI processing.

Do I need ManyChat Pro to use AI and webhooks?

Yes. ManyChat's Free plan is capped at 25 active contacts and basic flows, while native AI integrations and External Request webhooks require upgrading to the Pro tier (starting around $29/month billed annually).

Can Make automate Instagram DMs without ManyChat?

Technically yes via the Meta Graph API and webhooks, but you must create a Meta Developer App, pass Instagram messaging permissions review, and manually manage OAuth tokens and 24-hour window rules—which is why most teams keep ManyChat for the Instagram trigger layer.

How do I stop ManyChat's contact-based bill from growing forever?

Sync captured lead emails immediately to an owned email/funnel platform (such as Systeme.io) via webhook, then periodically archive inactive ManyChat subscribers who have not engaged within 30–60 days.
