How Queue Mode Architecture Works

In Queue Mode, responsibilities split cleanly across four layers:

  1. caddy terminates TLS (automatic Let's Encrypt HTTPS) and proxies traffic strictly to internal n8n-main:5678.
  2. n8n-main serves the web editor, schedules cron triggers, and receives inbound webhooks—then immediately enqueues jobs into Redis without blocking.
  3. redis (Bull queue) buffers pending workflow executions so traffic spikes never overwhelm your server.
  4. n8n-worker (1 to N replicas) pulls jobs from Redis, executes LLM/API nodes in parallel, and writes state to PostgreSQL 16.

Step 1: Production .env File

Create /opt/n8n-queue/.env (chmod 600 .env). Both n8n-main and every n8n-worker must share the exact same N8N_ENCRYPTION_KEY:

DOMAIN_NAME=agents.yourdomain.com
SSL_EMAIL=ops@yourdomain.com
TIMEZONE=UTC

# Generate with: openssl rand -hex 32
N8N_ENCRYPTION_KEY=replace_with_64_char_hex_encryption_key
N8N_USER_MANAGEMENT_JWT_SECRET=replace_with_64_char_hex_jwt_secret

DB_POSTGRESDB_DATABASE=n8n
DB_POSTGRESDB_USER=n8n_user
DB_POSTGRESDB_PASSWORD=ReplaceWithStrongPostgresPass2026!

QUEUE_BULL_REDIS_PASSWORD=ReplaceWithStrongRedisPass2026!

Step 2: Scalable docker-compose.yml (With Scaling Trap Fixed)

Notice two critical production details below:

  • No container_name: on n8n-worker: Many tutorials hardcode container_name: n8n-worker, which crashes the moment you run docker compose up -d --scale n8n-worker=3.
  • Explicit mem_limit caps: Guarantees a runaway LLM JSON loop inside a worker cannot OOM-kill PostgreSQL or Redis.
volumes:
  postgres_storage:
  redis_storage:
  n8n_storage:
  caddy_data:
  caddy_config:

networks:
  n8n-net:
    driver: bridge

x-n8n-env: &n8n-env
  N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
  N8N_USER_MANAGEMENT_JWT_SECRET: ${N8N_USER_MANAGEMENT_JWT_SECRET}
  DB_TYPE: postgresdb
  DB_POSTGRESDB_HOST: postgres
  DB_POSTGRESDB_PORT: 5432
  DB_POSTGRESDB_DATABASE: ${DB_POSTGRESDB_DATABASE}
  DB_POSTGRESDB_USER: ${DB_POSTGRESDB_USER}
  DB_POSTGRESDB_PASSWORD: ${DB_POSTGRESDB_PASSWORD}
  QUEUE_BULL_REDIS_HOST: redis
  QUEUE_BULL_REDIS_PORT: 6379
  QUEUE_BULL_REDIS_PASSWORD: ${QUEUE_BULL_REDIS_PASSWORD}
  EXECUTIONS_MODE: queue
  OFFLOAD_MANUAL_EXECUTIONS_TO_WORKERS: "true"
  EXECUTIONS_DATA_PRUNE: "true"
  EXECUTIONS_DATA_MAX_AGE: "168"
  GENERIC_TIMEZONE: ${TIMEZONE}
  NODE_ENV: production

services:
  postgres:
    image: postgres:16-alpine
    restart: unless-stopped
    mem_limit: 1536m
    environment:
      POSTGRES_DB: ${DB_POSTGRESDB_DATABASE}
      POSTGRES_USER: ${DB_POSTGRESDB_USER}
      POSTGRES_PASSWORD: ${DB_POSTGRESDB_PASSWORD}
    volumes:
      - postgres_storage:/var/lib/postgresql/data
    networks:
      - n8n-net
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${DB_POSTGRESDB_USER} -d ${DB_POSTGRESDB_DATABASE}"]
      interval: 5s
      timeout: 5s
      retries: 5

  redis:
    image: redis:7.2-alpine
    restart: unless-stopped
    mem_limit: 512m
    command: redis-server --appendonly yes --requirepass ${QUEUE_BULL_REDIS_PASSWORD}
    volumes:
      - redis_storage:/data
    networks:
      - n8n-net
    healthcheck:
      test: ["CMD", "redis-cli", "-a", "${QUEUE_BULL_REDIS_PASSWORD}", "ping"]
      interval: 5s
      timeout: 5s
      retries: 5

  n8n-main:
    image: docker.n8n.io/n8nio/n8n:latest
    restart: unless-stopped
    mem_limit: 1536m
    environment:
      <<: *n8n-env
      N8N_HOST: ${DOMAIN_NAME}
      WEBHOOK_URL: https://${DOMAIN_NAME}/
    ports:
      - "127.0.0.1:5678:5678"
    volumes:
      - n8n_storage:/home/node/.n8n
    networks:
      - n8n-net
    depends_on:
      postgres:
        condition: service_healthy
      redis:
        condition: service_healthy

  n8n-worker:
    image: docker.n8n.io/n8nio/n8n:latest
    restart: unless-stopped
    mem_limit: 1536m
    command: worker --concurrency=10
    environment:
      <<: *n8n-env
    volumes:
      - n8n_storage:/home/node/.n8n
    networks:
      - n8n-net
    depends_on:
      n8n-main:
        condition: service_started
      postgres:
        condition: service_healthy
      redis:
        condition: service_healthy

  caddy:
    image: caddy:alpine
    restart: unless-stopped
    mem_limit: 256m
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    networks:
      - n8n-net
    depends_on:
      - n8n-main

Step 3: Launch & Scale Workers Horizontally

Pair this with a standard Caddy reverse proxy (reverse_proxy n8n-main:5678 with response_header_timeout 300s), lock down UFW (22, 80, 443 only), and launch two parallel workers immediately:

docker compose up -d --scale n8n-worker=2
docker compose ps

Verify Redis queue connectivity and live worker registration:

docker compose logs --tail=30 n8n-worker

You should see n8n worker is now ready on both replicas. On an 8 GB RAM VPS (like Hostinger VPS KVM 2), 2 workers at --concurrency=10 comfortably process 20 concurrent AI agent workflows without slowing down the web UI.

Frequently Asked Questions

When should I upgrade self-hosted n8n from single-container to Queue Mode?

Switch to Queue Mode as soon as you run concurrent AI agent webhooks, scheduled cron jobs that overlap, or heavy LLM loops that make the n8n web editor laggy or cause webhook timeouts.

How much RAM do I need for n8n Queue Mode with PostgreSQL and Redis?

An 8 GB RAM KVM VPS (such as Hostinger KVM 2) is the comfortable production sweet spot: ~1.5 GB for PostgreSQL, ~512 MB for Redis, ~1.5 GB for n8n-main, and 1.5 GB each for 2 n8n-worker replicas.

Why did docker compose up --scale n8n-worker=3 fail in my setup?

Most failures happen because container_name: is hardcoded on the n8n-worker service in docker-compose.yml. Removing container_name lets Docker Compose assign unique names to each worker replica.

Do all n8n workers need the same N8N_ENCRYPTION_KEY?

Yes. Both n8n-main and every n8n-worker replica must receive the exact same N8N_ENCRYPTION_KEY environment variable so workers can decrypt stored API credentials from PostgreSQL.
