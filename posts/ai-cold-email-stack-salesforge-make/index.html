Why ESP Matching & Mailbox Rotation Matter in 2026

Google Workspace and Microsoft 365 spam filters now score sender reputation at both the domain and inbox level. Sending 400 cold emails from a single inbox triggers instant promotions-tab or spam-folder placement.

Salesforge solves this at the infrastructure layer:

  1. Unlimited Connected Mailboxes: Instead of paying per-inbox SaaS seats, you spread 1,000 daily sends across 25–30 warmed mailboxes (~35 emails/inbox/day).
  2. Automatic ESP Matching (Growth plan): Routes Google Workspace senders to Google recipients and Microsoft 365 senders to Outlook/Office 365 recipients, materially improving primary inbox placement.
  3. Built-in Warmforge Warm-up: Continuously exchanges natural engagement signals across your mailboxes so sender reputation stays healthy while campaigns run.
  4. Strict DNS Hygiene: Configure SPF, DKIM, and a monitoring DMARC record (v=DMARC1; p=none;) on every secondary outbound domain before sending a single live email.

The 4-Stage Automated Outbound Pipeline

Here is how engineering and growth teams wire Python / Make / n8n into Salesforge cleanly:

  1. Enrich & Deduplicate: Pull target accounts (Apollo, Apify, or your own scraper) into n8n or Make, stripping duplicates and existing customers.
  2. Hard-Gate Email Verification: Verify every address before touching your outbound sequence. Keep hard bounce rates strictly below 1–2%—bounces are the fastest way to burn a domain.
  3. Programmatic Enrollment via API: Push validated contacts with personalized variables (company_stack, recent_trigger) into a Salesforge sequence via REST API.
  4. Event-Driven Webhook Hygiene: Subscribe to Salesforge webhooks (reply_received, email_bounced, unsubscribed) so positive replies alert Slack immediately and bounces/unsubscribes are suppressed across your entire master database.

Copy-Paste Python Script: Pre-Flight DNS Check + Salesforge Webhook Hygiene

Before enrolling leads or listening to campaign events, run a lightweight Python FastAPI webhook receiver (hostable alongside n8n on Hostinger VPS) to enforce automatic bounce suppression and Slack notifications:

import os
import json
import urllib.request
from fastapi import FastAPI, Header, HTTPException
from pydantic import BaseModel

app = FastAPI()
WEBHOOK_TOKEN = os.environ.get("OUTBOUND_WEBHOOK_TOKEN", "replace-me")
SLACK_WEBHOOK_URL = os.environ.get("SLACK_WEBHOOK_URL", "")
SUPPRESSION_FILE = "suppression_list.jsonl"


class SalesforgeEvent(BaseModel):
    event_type: str  # email_sent | reply_received | email_bounced | unsubscribed
    lead_email: str
    campaign_id: str
    snippet: str = ""


def _notify_slack(text: str) -> None:
    if not SLACK_WEBHOOK_URL:
        return
    req = urllib.request.Request(
        SLACK_WEBHOOK_URL,
        data=json.dumps({"text": text}).encode("utf-8"),
        headers={"Content-Type": "application/json"},
        method="POST",
    )
    urllib.request.urlopen(req, timeout=5).read()


@app.post("/webhooks/salesforge")
async def handle_outbound_event(
    event: SalesforgeEvent,
    x_webhook_token: str = Header(default=""),
):
    if x_webhook_token != WEBHOOK_TOKEN:
        raise HTTPException(status_code=401, detail="Unauthorized webhook")

    if event.event_type in {"email_bounced", "unsubscribed"}:
        with open(SUPPRESSION_FILE, "a", encoding="utf-8") as f:
            f.write(json.dumps({"email": event.lead_email.lower(), "reason": event.event_type}) + "\n")
        return {"status": "suppressed", "email": event.lead_email}

    if event.event_type == "reply_received":
        _notify_slack(
            f":dart: Positive reply from *{event.lead_email}* (campaign `{event.campaign_id}`):\n> {event.snippet[:240]}"
        )
        return {"status": "notified"}

    return {"status": "ignored", "event_type": event.event_type}

Pair this receiver with a pre-enrollment check in Make or n8n that skips any email present in suppression_list.jsonl—guaranteeing you never accidentally re-email a bounced address or opt-out across future campaigns.

Frequently Asked Questions

How much does Salesforge cost in 2026?

Salesforge offers flat-rate tiers: Pro starts at $48/month (~$29–$40/mo billed annually) for 5,000 emails/month and 1,000 active contacts, while Growth is $96/month (~$58–$80/mo annual) for 50,000 emails/month, unlimited seats, unlimited mailboxes, ESP matching, and API/MCP access.

Can I connect Salesforge to Make or n8n via API and webhooks?

Yes. Salesforge provides a public API and event webhooks (such as email_sent, reply_received, and email_bounced) that integrate directly with n8n and Make for automated lead enrollment, CRM logging, Slack alerts, and bounce suppression.

How many cold emails should I send per mailbox per day in 2026?

Keep daily volume modest—typically 30 to 50 emails per warmed mailbox per day—and scale total volume horizontally across multiple secondary domains and mailboxes rather than hammering a single inbox.

Why shouldn't I send cold outreach from a raw VPS or my main app domain?

Cold outbound carries higher complaint and bounce risk than transactional email. Sending from your primary domain can put password resets and customer invoices into spam, while raw VPS IPs lack warm reputation and ESP matching.
